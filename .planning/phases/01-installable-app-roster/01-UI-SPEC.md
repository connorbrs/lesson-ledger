# Phase 01 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Locked user decisions (from the orchestrator brief, not re-asked):** native iOS feel (system font, grouped inset lists, iOS-style nav bars, bottom tab bar); theme follows the iPhone setting (light and dark); bottom tabs Log · Sessions · Summaries · People · Settings with unbuilt tabs hidden; iPhone portrait only, installed as a standalone home-screen PWA with safe-area insets respected; no component library, hand-written CSS with design tokens; hours format "1.5 h (1:30)" and weeks Mon–Sun (not exercised in Phase 1 UI beyond the period label).

**User decision 2026-10-18 (copy exception, extended the same day):** keep iOS-native "Cancel" and "Save" in sheet nav bars, and keep "Cancel" in confirmation alerts (delete and discard). The sheet title, or the alert title and message, supplies the noun (see Copywriting Contract). This is the only approved exception to the verb+noun rule.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap in tab bar, inline glyph spacing |
| sm | 8px | Group header bottom gap, group footer top gap, banner internal gaps |
| md | 16px | Grouped-list side inset, row horizontal padding, sheet padding, banner padding |
| lg | 24px | Empty-state vertical padding, sheet top spacing before first group |
| xl | 32px | Gap between grouped sections (People families, Settings groups) |
| 2xl | 48px | Empty-state block separation from top nav |
| 3xl | 64px | Not used in Phase 1 |

Exceptions (each is a deliberate iOS-native or touch-target value):
- Row vertical padding: 12px (between sm and md; multiple of 4).
- Row minimum height: 44px (Apple touch-target minimum).
- Icon and text button minimum hit area: 44×44px, glyph 24px centered.
- Nav bar content height: 44px (plus `env(safe-area-inset-top)`).
- Tab bar content height: 48px (system tab bar is 49pt; 48 keeps the multiple-of-4 rule), plus `env(safe-area-inset-bottom)`.
- Segmented control height: 32px.
- Alert width: 272px. iOS's system alert is 270pt wide. 272 is the nearest multiple of 4, so the alert stays on the spacing grid and differs from the native width by 2px.
- Radii: 12px for grouped lists, cards, banners and sheet top corners; 8px for the segmented control. Radii are declared here so they are not mistaken for spacing.

Stroke widths (line weights, not spacing; listed so they are not read as off-grid spacing):
- Input focus outline: 2px.
- Hairline separator: 0.5px (1px fallback).
- Icon stroke: 2px.

Safe areas: every fixed or edge-attached element (nav bar, tab bar, sheet header, sheet footer, scroll container bottom) adds `env(safe-area-inset-*)` to its declared height. Nothing is hidden under the notch or the home indicator.

## Typography

Three sizes and two weights only.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 34px | 600 | 1.2 | Large titles on the People and Settings tab roots |
| Heading | 17px | 600 | 1.3 | Inline nav titles, sheet titles, family names as group headers, alert title |
| Body | 17px | 400 | 1.3 | Row labels and values, student names, input text, button labels, banner body, empty-state body |
| Label | 13px | 400 | 1.3 | Group footers, helper and validation captions, tab bar labels, storage notes |

Notes:
- Line height is 1.3 for body, not 1.5. This is the iOS row metric (17px on 22px leading) and is a deliberate native-feel choice. Long paragraphs (empty-state body) use the same 1.3.
- Input text is 17px, not smaller. Browsers below 16px make iOS Safari zoom the page on focus.
- Weight 600 is used for emphasis. The Save button and the selected segment are 600.

## Layout and Navigation Contract

### Device and document

- iPhone portrait only, designed for 375 to 430 CSS px width. Landscape is not designed; content scrolls and must not break.
- Target is the standalone home-screen app. The Safari tab is supported only as the warning state (see Safari-tab banner).
- Head tags:
  - `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`
  - `<meta name="apple-mobile-web-app-capable" content="yes">`
  - `<meta name="apple-mobile-web-app-status-bar-style" content="default">`
  - `<meta name="apple-mobile-web-app-title" content="Lesson Ledger">`
  - `<meta name="theme-color" media="(prefers-color-scheme: light)" content="#F2F2F7">`
  - `<meta name="theme-color" media="(prefers-color-scheme: dark)" content="#000000">`
- Manifest: `name` and `short_name` "Lesson Ledger"; `display` standalone; `orientation` portrait; `background_color` #F2F2F7; `theme_color` #F2F2F7. `start_url` and `scope` equal the GitHub Pages base path (taken from Vite `base`).
- App icon: solid #00707A full-bleed square with one centered white clock glyph (ring, two hands and a center dot; about 60% of icon width), still full-bleed and opaque. 180×180 PNG for `apple-touch-icon`, 512×512 PNG for the manifest. No text, no transparency (iOS masks the corners).

### Top-level structure

- Bottom tab bar shows People and Settings only. Log, Sessions and Summaries are not rendered: no disabled placeholders, no "coming soon" tabs. Two tabs split the width equally.
- Launch default tab: People.
- Each tab root has a large title (Display, left-aligned, 16px inset) under a 44px nav bar.
- Pushed screens use an inline title (Heading, centered). The Back button is labeled with the previous screen's title.
- Record names never appear in nav titles. Titles are fixed words, so they never truncate.

### Focal point per screen

One focal point per screen and state. Everything else on the screen is subordinate to it.

| Screen | State | Focal point |
|--------|-------|-------------|
| People (tab root) | Populated | Large title "People" (Display) |
| People (tab root) | Empty | "Add Family" button (accent fill), centered under the "No families yet" heading |
| Family sheet | New or edit | Name field, focused on open |
| Student sheet | New or edit | Name field, focused on open |
| Family picker | Populated | Accent checkmark on the chosen family row |
| Archived | Populated | Inline title "Archived" (Heading) |
| Settings (tab root) | Any | Large title "Settings" (Display); the Persistent storage value is the only row whose value changes state |
| Records error | Any | Heading "Can't open your records" |

### Chrome dimensions

- Nav bar: 44px content plus `env(safe-area-inset-top)`. Surface background. A 0.5px separator appears under the bar only when content scrolls beneath it.
- Tab bar: 48px content plus `env(safe-area-inset-bottom)`. Surface at 92% opacity with `backdrop-filter: blur(20px) saturate(180%)`; solid surface when unsupported. Tab icons 24px; label Label style with 4px (xs) gap below the icon.
- Scroll container bottom padding: 48px + `env(safe-area-inset-bottom)` + 16px, so the last row is never hidden behind the tab bar.

### Grouped list

- Group: horizontal margin 16px, surface background, radius 12px, clipped.
- Row: minimum height 44px, padding 12px 16px, Body text. Values are right-aligned in text-secondary. A 0.5px separator sits inset 16px from the left, and there is none after the last row.
- Group header (family name): Heading style, padding 0 16px 8px.
- Group footer: Label style, text-secondary, padding 8px 16px 0.
- Gap between groups: 32px (xl).
- Navigable rows show a 12px-wide chevron in text-secondary on the right.
- Pressed row: `--color-pressed` background, applied immediately. No hover states (iPhone).

### Sheets, alerts, banners

- Sheets: full-height, rounded top corners of 12px, slide up 350ms ease-out. Header is a 44px nav bar with Cancel (left, accent) and Save (right, accent, 600). Sheet title is Heading and centered. Cancel and Save sit in the header, not at the bottom, so the keyboard never covers them. Sheets are not swipe-dismissible in Phase 1.
- Name field receives focus on sheet open, so the keyboard appears immediately.
- Discard: when Cancel is tapped on a dirty form, a dialog asks to discard. Save writes immediately. There is no draft autosave.
- Alert (delete confirmation and discard confirmation): centered surface card, 272px wide, radius 12px, Heading title, Body message. Two full-width 44px buttons stacked with separators. Delete alert: Cancel (accent, regular) and "Delete Family" or "Delete Student" (destructive, 600). Discard alert: "Keep Editing" (accent) and "Discard Changes" (destructive, 600).
- Banners sit in flow at the top of the scroll content and push content down. They never float over content. Update banner: 16px margin, surface, radius 12px, padding 16px. Safari-tab banner: full width under the nav bar, surface, 0.5px bottom separator, no radius, no icon.
- Input row: Body 17px, text-primary, placeholder text-secondary, no box border (grouped-row style). Focus shows a 2px accent outline inset in the row. Inputs carry `autocapitalize="words"`, `autocorrect="off"` and `enterkeyhint="done"`, and the focused field scrolls above the keyboard.
- Segmented control: two segments (Weekly / Monthly) on the Family sheet and three segments (Swim / Math / Both) on the Student sheet, with identical styling: height 32px, radius 8px, Body text. Selected segment: accent fill with on-accent text, weight 600. Unselected: text-primary on surface.

### Motion and touch

- Push: slides from right, 300ms ease-in-out.
- Sheet: slides up, 350ms ease-out. Dismiss mirrors it.
- `prefers-reduced-motion: reduce`: all of the above become a 150ms opacity cross-fade.
- Touch feedback: pressed-row background for rows; text buttons drop to 50% opacity while active.
- `-webkit-tap-highlight-color: transparent`. No bounce, no haptics.

### Layout at 200% zoom

- Lists reflow to single column; no fixed-width containers. Verified on device (see backstop rows in UI Considerations).

## Assumptions

Phase 1 has no sessions, so the delete rule is implemented against the (empty) sessions table. Families and students can be hard-deleted until Phase 2 adds sessions.

1. **Delete rule.** Delete is shown only when the record has no history. A family with any students (active or archived) cannot be deleted; its students must be removed first. A student with any session cannot be deleted. Both are implemented now against the sessions table and currently always allow delete.
2. **Archive.** Archive has no confirmation because it is reversible from the Archived screen. Archiving a family hides it and its students from the roster; students keep their own archive state, and restoring a family does not auto-restore its students.
3. **No swipe actions in Phase 1.** Records are edited by tapping. Sheets are not swipe-dismissible; Cancel is the exit.
4. **Hidden tabs.** Log, Sessions and Summaries are not rendered until their phases. People is the launch tab.
5. **Status bar.** `apple-mobile-web-app-status-bar-style` is `default` with per-scheme `theme-color`. Whether iOS tints the status area from `theme-color` in standalone mode is unverified and is a device check.
6. **Launch screen.** No `apple-touch-startup-image` set in Phase 1. iOS may flash white on launch in dark mode. If that is seen on device, add startup images in a later pass.
7. **Safari detection.** Standalone mode is detected with `matchMedia('(display-mode: standalone)')` or `navigator.standalone === true`. The Safari tab and the home-screen app are assumed to keep separate storage (from the research summary, MEDIUM confidence). The Phase 1 device spike confirms it.
8. **iOS version.** The minimum iOS version is still undecided (STATE.md blocker). The UI assumes the current iOS. `persist()` and `estimate()` degrade to "Not supported" or "Unavailable" rather than breaking.
9. **Dark mode.** Follows `prefers-color-scheme` only.
10. **Accent.** Teal #00707A (light) and #5FD3DE (dark) is a proposed choice from the "surprise me" brief. It is set in two tokens and can be swapped without touching components.
11. **Name length.** 60 characters, a chosen default.
12. **Update timing.** "Update App" reloads the app immediately, so unsaved input on screen is lost. The banner copy tells the user to save first.
13. **Font.** System stack only, no web font. Chosen for native feel and zero download cost.
