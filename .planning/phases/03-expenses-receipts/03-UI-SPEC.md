# Phase 03 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Inherited, not redefined:** every token, type role, component and copy rule in `01-UI-SPEC.md` and `02-UI-SPEC.md` applies unchanged. This contract adds Phase 3 surfaces and states only. No new color tokens, type sizes, weights or component library.

**Locked decisions (03-CONTEXT.md, not re-asked):** D-01 Expenses section lives in the shared session form and saves in one transaction with the session. D-02 US dollars, integer cents, shown as "$12.50". D-03 one expense is amount (required, more than $0) plus description (required); its date is the session's date. D-04 "Expenses $12.50" line on Sessions rows, only when the session has expenses. D-05 session delete names the counts. D-06 backup stays one JSON file, schemaVersion 2 embeds photos; v1 still restores. D-07 restore clears and replaces `expenses` and `attachments` in one transaction and validates every photo entry first. Split: equal by default; typing one family's share fills the other with total minus share; odd cent goes to the first family in pick order; shares stored in cents.

## Layout and Navigation Contract

### Screen map (Phase 3 additions)

| Screen | Entry | Contents | Navigation |
|--------|-------|----------|------------|
| **Session form (Log and Edit Session)** | Existing | New group **Expenses** after the credit groups and before the backup card (Log) or the Delete Session group (Edit). Rows: one per expense, then "Add Expense". | Tap an expense or Add Expense pushes the **Expense editor**. Log Session and Save write the session, its expenses and receipt photos together. |
| **Expense editor** (push) | Expenses group row | Nav bar: back label is the parent title ("Log" or "Edit Session"), title "New Expense" or "Expense", "Save" right (accent, 600). Groups: Amount and Description; Receipts; Split (two-family swim only); Delete Expense (existing expenses only). | Save returns to the session form with the expense staged. Nothing is written until the session saves. Back with unsaved changes uses the existing discard handling for the session. |
| **Receipt viewer** (push over the editor) | Tap a thumbnail | Nav bar: back label "Expense", title "Receipt 1 of 3". Full photo, fitted, pinch-zoom native. Bottom row "Remove Photo". | Back returns to the editor. Remove Photo opens the remove alert; confirmed removal returns to the editor. |

Expense editor and receipt viewer are pushed layers. Inside the Edit Session sheet they sit in the sheet's overlay, as the Student picker does. Tab bar stays inert behind them.

### Expenses group (session form)

- **Header:** "Expenses" (Heading).
- **Rows:** one per expense, in entry order. Each row is a button (44px min, padding 12px 16px) with:
  - Left (flex, clamped to 2 lines): description (Body). Second line (Label, secondary): "No receipts", "1 receipt" or "2 receipts". For a two-family swim, a further clamped line: "Smith $6.25 · Jones $6.25".
  - Right (fixed, right-aligned, Body, tabular): amount "$12.50".
- **Last row:** "Add Expense" (accent text, regular). Always present.
- **Footer:** "Total {total}." (e.g. "Total $12.50.") (Label, secondary) when there is at least one expense. With none: "Expenses are saved with this session."
- **Zero expenses:** the group shows only the Add Expense row and the empty footer. No separate empty state.
- **Draft:** expenses live in the form state. Changing the form's families does not clear expenses; the split group in the editor follows the rules below.

### Expense editor field contract

- **Title:** "New Expense" when adding, "Expense" when editing.
- **Amount row:** label "Amount" (Body). Right side: a secondary "$" prefix, then a numeric input, `inputmode="decimal"`, placeholder "0.00", 96px, right-aligned. Accepts digits with at most one decimal point and at most two decimal places. The "$" is display only; the user does not type it.
- **Amount captions** (Label, destructive, under the row):
  - Not a valid amount, or more than two decimals: "Use dollars and cents, like 12.50."
  - Zero: "Amount must be more than $0.00."
  - Captions show after the field loses focus once (same touched rule as the minute fields). Save is disabled while the amount is invalid, zero or blank.
- **Description row:** label "Description" (Body; the label column is 96px in this group so the word does not wrap), text input, placeholder "e.g. Pool entry fee", `maxlength="80"`, `autocapitalize="sentences"`, `enterkeyhint="done"`. Save is disabled while blank after trimming. No caption; a blank field simply keeps Save disabled.
- **Amount changes reset the split to equal** (see Split).
- **Save:** disabled while the amount or description is invalid, or while any photo is still processing.

### Receipts group (expense editor)

- **Header:** "Receipts" (Heading). **Footer (Label, secondary):** "Photos stay on this phone and are included in backups."
- **Grid:** wrapping grid of 72×72 thumbnails in the order added, then the Add Photo tile last. Each thumbnail is a button labelled "Receipt {n} of {N}, open". The empty state is the Add Photo tile alone.
- **Add Photo tile:** 72×72, dashed border, plus glyph above "Add Photo" (Label, accent). Tap calls the hidden `<input type="file" accept="image/*" multiple>`. iOS offers Take Photo, Photo Library and Choose File. Disabled while photos are processing.
- **Processing:** one `--color-pressed` tile per photo still being prepared, labelled "Processing…" (Label, secondary). The Add Photo tile is disabled. Announced once as status ("Processing photos").
- **Loading (existing expense):** thumbnails read from the session's live query. A placeholder tile in `--color-pressed` shows until the Blob resolves. No spinner.
- **Failure captions** (Label, destructive, below the grid, one caption per batch):
  - Too large: "This photo is too large to add. Choose a smaller photo." (source over 25 MB; see Assumptions).
  - Cannot read (one): "This photo couldn't be read and wasn't added. Choose it again or take a new photo."
  - Cannot read (several): "{N} photos couldn't be read and weren't added. Choose them again or take new photos."
  - Successful photos in the same batch are added; failed ones are not. A failure never removes existing photos.
  - Captions clear on the next successful add.
- **Staged:** added photos and removed photos are saved only when the session saves. Cancel or discard drops them.

### Receipt viewer

- **Nav:** back label "Expense", title "Receipt {n} of {N}".
- **Image:** fitted to the area with `object-fit: contain`, centered, `#000000` surround. Native pinch-zoom and pan. No paging control: back and tap another thumbnail.
- **Image failure:** "This photo couldn't be shown. Remove it and add it again." (Label, destructive) centered in the area; Remove Photo stays.
- **Footer:** "Remove Photo" (destructive, regular), 44px, above the home indicator. Tap opens the remove alert.
- **Remove alert:** title "Remove this receipt photo?"; message "It's deleted when you save the session."; buttons "Cancel" (accent, regular) and "Remove" (destructive, 600). Cancel changes nothing. Remove returns to the editor with the thumbnail gone.

### Split group (two-family swim only)

- **Shown only when** the session form is a swim with students from two different families (the `needsCreditGroups` rule). Otherwise the group is absent and the expense belongs to the one family.
- **Header:** "Split" (Heading). **Header action:** "Split Equally" (accent text, regular), shown only when the split is overridden.
- **Rows:** one per family, in pick order. Each row: family name (Body, clamp 2 lines) on the left; amount input on the right ("$" prefix, 96px, decimal, right-aligned, 17px).
- **Default:** equal split. With an odd number of cents the first family in pick order carries the extra cent ($10.01 gives $5.01 and $5.00).
- **Override:** typing in either family's input sets that share, and the other share becomes total minus that share, live. Both inputs stay editable. Shares are always stored in cents and sum exactly to the total.
- **Captions** (Label, destructive, under the row): not a valid amount: "Use dollars and cents, like 6.25." A share above the total: "A share can't be more than {total}." Save is disabled while a caption shows.
- **Footer (Label, secondary):** "Split equally by default. Type one family's share and the other fills in to make the total."
- **Amount change:** resets the split to equal.
- **Split Equally:** restores the equal split and hides itself.

### Delete Expense

- **Row:** group of its own at the bottom of the editor: "Delete Expense" (destructive, regular). Existing expenses only.
- **Alert:** title "Delete this expense?". Message, only when the expense has photos: "This also deletes {N} receipt photos." (singular for one). No message when there are no photos. Buttons "Cancel" (accent, regular) and "Delete Expense" (destructive, 600).
- **Effect:** removes the expense and its photos from the staged session. Nothing is written until the session saves.

### Sessions list (Phase 2 change)

- **Row right column** gains a third line after Lesson and Activity: "Expenses $12.50" (Label, text secondary). Shown only when the session has expenses. The value is the session's expense total.
- **Row left column and the rest of the row:** unchanged.

### Session delete alert (Phase 2 change)

- **Title:** "Delete this session?" (unchanged).
- **Message:** "This can't be undone." when the session has no expenses. With expenses: "This also deletes {E} expenses and {P} receipt photos. This can't be undone." Pluralize each count with Intl.PluralRules. Omit the photo clause when there are zero photos: "This also deletes 1 expense. This can't be undone."
- **Buttons, failure line:** unchanged from Phase 2.

### Save and discard (session form)

- **Save failure:** existing copy "Couldn't save. Your phone may be low on storage. Nothing was changed. Try again." (Label, destructive, above Log Session or in the sheet). The form keeps every value, including staged expenses and photos.
- **Discard dialog:** existing wording. A staged expense, photo or removal counts as a change.
- **Log tab:** Log Session saves the expenses and photos together, then the form resets to its pre-filled state (expenses and photos cleared). Log Session is disabled while photos are processing or an expense is invalid.

### Backup (Settings, Phase 2 extension)

- **Backup footer and busy states:** unchanged except the footer copy in the Amendments section.
- **Restore validation:** an invalid photo entry uses the existing "damaged" message. A v2 file opened by an app that cannot read v2 uses the existing "newer version" message.
- **Restore success and confirm:** the counts include expenses and receipt photos (Copywriting).

### Motion and touch

- Phase 1 and 2 motion unchanged. Expense editor and receipt viewer use the push animation (300ms; reduced motion 150ms cross-fade).

### Money format

One formatter for every money value (expense rows, totals, splits, Sessions line, later summaries):

- Storage: integer cents. Display: `$` + thousands separator + two decimals. Examples: 1250 → "$12.50"; 100000 → "$1,000.00"; 5 → "$0.05".
- Input parses "12", "12.5", "12.50" to cents. Never float arithmetic on stored values.
- No currency setting; the symbol is fixed to "$".

## Assumptions

Resolved by the researcher under the Phase 2 conventions. Each is reversible before build.

1. **Source size limit: 25 MB per photo** before downscale. Larger files get the too-large caption. Chosen to stop a full-resolution original from exhausting memory; the device spike confirms.
2. **Description max 80 characters** (`maxlength`), no caption at the limit.
3. **No cap on the amount.** Integer cents make any entered value exact.
4. **Amount change resets the split to equal.** Avoids stale shares after the total changes.
5. **Split Equally action** appears only when the split is overridden.
6. **Expense editor Save stages; the session writes everything.** Expense delete and photo removal are also staged until the session saves (D-01).
7. **Photo removal lives in the viewer** with a confirm alert. The thumbnail itself is a single 72px button, so no small corner target is needed.
8. **Viewer surround is `#000000`** in both modes, the single literal color in Phase 3.
9. **Expenses group sits after the credit groups** and before the backup card, so the minute and credit rules stay together at the top.
10. **Single-family or no-student sessions** show no split. The expense belongs to the one family.
11. **Log tab keeps staged expenses across tab switches** (existing draft behavior). Log Session clears them.

## Open items for the planner

- **Split when the families change:** if a draft's two families change while an expense has an overridden split, the stored shares refer to the old families. The data layer resets that expense to equal; the UI must not show stale shares. The planner assigns the reset to the session-save path.
- **Save gating and photo constants:** Log Session and the editor Save share one "photos processing" flag. Photo constants: the 25 MB source limit, the 1600 px long edge and the JPEG quality live in one module so the device spike can tune them without a UI change.
- **Backup photo entries:** validation of each photo entry (type, size, base64, `expenseId` reference) belongs to the restore path; its failure maps to the existing "damaged" message only.
