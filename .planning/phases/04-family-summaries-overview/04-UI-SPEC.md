# Phase 04 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Inherited, not redefined:** every token, type role, component and copy rule in `01-UI-SPEC.md`, `02-UI-SPEC.md` and `03-UI-SPEC.md` applies unchanged. This contract adds Phase 4 surfaces and states only. No new color tokens, no new UI type sizes or weights, no component library.

### Summaries tab

- **Nav:** bare (safe area only). Large title "Summaries" (Display).
- **Group (no header):** one row per **active** family, in the same order as People. Archived families are not listed.
- **Row:** left, clamped to 2 lines: family name (Body), then second line (Label, secondary): "Weekly · Oct 12–18" or "Monthly · October 2026". With no sessions in that period the second line ends "· No sessions". Right: a status pill when applicable ("Sent" or "Changed since sent"), then a chevron. Pills appear only for a family whose period has a sent record.
- **Default period:** the most recent complete period before today: the Monday–Sunday week before the current week, or the calendar month before the current month, per the family's `period`.
- **Footer (Label, secondary):** "Each family's most recent complete week or month. Families with no sessions are listed but have nothing to send."
- **Empty (no active families):** heading and body from Copywriting; no action.

### Family Summary (push layer)

Top to bottom:

1. **Nav bar:** back label "Summaries"; title = family name (Heading, one line, ellipsis). No right action.
2. **Period navigation:** ‹, period label (Heading, centered), ›. ‹ moves back one period with no limit. › is disabled on the default period (the most recent complete period), so the summary never shows an incomplete period. When not on the default period, a "Last Week" / "Last Month" accent action sits beneath. Period label format as the Sessions label.
3. **Sent group** (hidden when the period has zero sessions):
   - Row "Status" (Body) with value: "Not sent", "Sent Oct 19, 2:40 PM", or "Changed since sent" (after an edit in a sent period).
   - Action row: "Mark as Sent" when not sent; "Mark as Sent Again" when changed since sent; "Mark as Not Sent" (neutral) when sent and unchanged.
   - Footer (Label, secondary): "Marking as sent records this only. Copy and Share never mark it."
   - Failure caption (destructive, Label) replaces the footer until the next attempt: "Couldn't mark as sent. Nothing was changed. Try again."
4. **Warnings group** "Check before sending" (Heading), shown only when at least one warning exists. One Body row per warning with the warning icon. Footer (Label, secondary): "Warnings never block Copy or Share."
   - Expense without a receipt: "No receipt: {description}, {amount} ({Mon D})". Example: "No receipt: Pool entry fee, $12.50 (Oct 18)".
   - Session with zero minutes: "No lesson or activity minutes: {Subject}, {Mon D}". Example: "No lesson or activity minutes: Swim, Oct 18".
   - Rows are not tappable in this phase.
5. **Message group** "Message" (Heading), header action "Copy Message" (accent text, regular):
   - **Stale banner** (first row, only when the saved message is older than the current hours): text "Hours changed since you edited this message" (Body) and "Rebuild Message" (accent). The saved text stays in the box.
   - **Textarea:** `lang="tr"`, `autocorrect="off"`, `spellcheck="false"`, `aria-label="Message to parents"`. Shows the saved text when one exists; otherwise the generated text.
   - **Save Message row:** accent 600 when the text differs from the saved text and is not blank; disabled otherwise. Success shows "Saved ✓" for 1.5 s (disabled). Failure caption above the row (destructive, Label): "Couldn't save the message. Your phone may be low on storage. Nothing was changed. Try again."
   - **Footer (Label, secondary):** "Edit any line. Copy uses the text in this box, saved or not. Save Message keeps it for next time."
6. **Sticky footer above the tab bar:** a caption line when one applies (see States), then "Share PDF" (primary, full width).

## Turkish Output (parent-facing: message and PDF)

### Formatters (one module, used by message and PDF)

- **Hours:** `{decimal} saat ({h:mm})`. Decimal comma; up to 2 decimals, trailing zeros trimmed; the same rounding as the shared formatter (half up). Zero reads `0 saat (0:00)`.
  - 45 min → "0,75 saat (0:45)"; 15 min → "0,25 saat (0:15)"; 60 min → "1 saat (1:00)"; 105 min → "1,75 saat (1:45)"; 22.5 min → "0,38 saat (0:23)".
- **Amounts:** the Phase 3 money formatter: "$" with a period decimal, "$12.50" (D-03). Thousands use a comma: "$1,000.00".
- **Session date:** weekday first, built from `Intl.DateTimeFormat('tr-TR')` parts: "Pzt 12 Eki". The tr-TR default order puts the weekday last ("12 Eki Pzt"), so the template assembles the parts itself.
- **Period label:** same month "12–18 Ekim 2026"; across months "28 Eylül – 4 Ekim 2026"; across years "28 Aralık 2026 – 3 Ocak 2027"; monthly "Ekim 2026".
- **Subjects:** "Yüzme" (swim), "Matematik" (math).

### Message templates (exact)

```
{family} ailesi — {period}

{date} · {subject} · ders {lesson}, aktivite {activity}
(one line per session, oldest first; blank line after the list)

Toplam ders {lessonTotal}
Toplam aktivite {activityTotal}
Masraflar {expenseTotal} (fişler PDF'te)
```

- The **Masraflar** line is shown only when the period has expenses for this family. It reads "Masraflar {expenseTotal}" without "(fişler PDF'te)" when no expense in the period has a receipt photo.
- `{expenseTotal}` is this family's share of the expenses (D-07).
- Travel never appears. Half-credit sessions show credited time only (D-06).

**Example (Smith family, weekly period, one swim and one math session):**

```
Smith ailesi — 12–18 Ekim 2026

Pzt 12 Eki · Yüzme · ders 0,75 saat (0:45), aktivite 0,25 saat (0:15)
Çar 14 Eki · Matematik · ders 1 saat (1:00), aktivite 0 saat (0:00)

Toplam ders 1,75 saat (1:45)
Toplam aktivite 0,25 saat (0:15)
Masraflar $18.75 (fişler PDF'te)
```

### PDF layout

- **Page:** US Letter, 612 × 792 pt. Margins 48 pt on all sides. Content width 516 pt.
- **Font:** a Turkish-capable sans serif embedded in the PDF module only: Noto Sans Regular and Bold, subset to Basic Latin, Latin-1 and Latin Extended-A, vendored with its OFL license file. Built-in Helvetica cannot draw ş, ğ, ı, İ, Ş or Ğ (outside WinAnsi), so the embedded font is required. Weights: 400 and 600 mapped to Regular and Bold.
- **Sizes (PDF only, in points):** 16 (header, bold), 12 (section headings, bold), 10 (body and table cells, regular), 8 (page footer and receipt sublines). Line height 1.3.
- **Page 1 onward, in order:**
  1. **Header (16 pt bold):** "{Instructor} — {Family} ailesi — {Period}". The instructor part and its dash are omitted when the name is blank.
  2. **Subline (10 pt):** "Ders ve aktivite süreleri. Yolculuk süresi dahil değildir."
  3. **Dersler** (12 pt bold): table with columns Tarih (date) 80 pt, Konu (subject) 72 pt, Öğrenci (this family's students only) 164 pt, Ders (lesson, credited) 100 pt, Aktivite (activity, credited) 100 pt. Rows wrap to 2 lines; the header row repeats on a new page as "Dersler (devam)".
  4. **Masraflar** (12 pt bold), only when expenses exist: table with Tarih, Açıklama (description, wraps), Toplam (full amount), Aile payı (this family's share). Amounts right-aligned.
  5. **Toplam** (12 pt bold): three right-aligned lines: "Toplam ders {L}", "Toplam aktivite {A}", "Masraflar (aile payı) {E}".
  6. **Fişler** (12 pt bold), new page, only when receipts exist. Two receipt slots per page, top to bottom, in expense entry order then photo order. Each slot: image fitted (contain) into 516 × 280 pt, centred; caption (10 pt) below: "{description} — {amount}", with " ({k}/{n})" when the expense has more than one photo. Slot height 320 pt including caption and gap.
  - **Page footer (8 pt, centred, in the bottom margin):** "{Family} ailesi — {Period} · Sayfa {n} / {N}".
- **Totals source:** the same computation as the message (SUM-06 and D-13). The PDF never reads the edited message text.
- **File name:** ASCII-folded family slug (ş→s, ğ→g, ı and İ→i, ç→c, ö→o, ü→u, lowercase, other characters to hyphens), then `-{YYYY-MM-DD}-{YYYY-MM-DD}.pdf` for weeks or `-{YYYY-MM}.pdf` for months.
- **Memory:** pages are built in sequence and each receipt Blob is decoded once. The build is per family, on demand, never for all families.
- **Any receipt that fails to load fails the whole build.** A PDF with a missing receipt is wrong, so no partial file is produced.

## Assumptions

Each is decided here and reversible before build.

1. **Default period:** the Monday–Sunday week or calendar month before the current one. ‹ has no limit; › stops at the default period, so incomplete periods are never summarized.
2. **Archived families** are hidden from Summaries (FAM-04). Past summaries of an archived family are not reachable in v1.
3. **Message header** omits the instructor name (the phone's Messages thread already shows the sender). The PDF header includes it when set (D-10).
4. **Session lines** have no student names (D-05). The PDF Öğrenci column lists only this family's students.
5. **Message order** is chronological (oldest first) so parents read top to bottom. The app's Sessions list stays newest first.
6. **Zero minutes** means the family's credited lesson and activity are both zero. Travel does not count.
7. **Travel in the personal view** is counted in full wherever it appears. Travel has no credit option, so a shared session's travel is shown in full on each family and student row. Subject rows count it once. Family and student rows can therefore add up to more than the total. The footer says so.
8. **Student rows** show each student the credited time of their family's session credit. Siblings each show the family's credited time (credit is per family; LOG-06 counts siblings once for that family).
9. **Message edits get one added confirm** (Rebuild Message), since a rebuild discards the user's text. D-09 required the banner, not the confirm.
10. **Mark as Not Sent** is added so an accidental tap can be undone. It has no confirm.
11. **"(fişler PDF'te)"** is conditional on the period having receipt photos (see Message templates).
12. **Dates in the message and PDF** use the tr-TR month names and weekday-first order built from Intl parts (see Formatters).
13. **Amounts** keep the "$" and period decimal inside Turkish text (D-03). Thousands use a comma, as in the Phase 3 money formatter.
14. **Instructor name** is optional. Blank omits it from the PDF header.
15. **Warnings are not tappable** in this phase.
16. **Calendar note:** the CONTEXT examples "Pzt 13 Eki" and "13–19 Ekim 2026" do not match the 2026 calendar (13 October 2026 is a Tuesday, and the Monday–Sunday week is 12–18 October). This contract uses Monday-anchored examples. The formatter takes its values from the real dates, so the examples are illustrative only.
17. **Tab label "Summaries"** must fit a 64px tab at 320px device width. Verified in the device check; no size change is allowed.
