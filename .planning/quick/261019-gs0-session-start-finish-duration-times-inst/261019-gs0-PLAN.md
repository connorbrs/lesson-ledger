<objective>
Replace the 30/45/60 minute presets in the session form with Start, Finish and Duration times, so a session is logged as a real start-and-finish record. Start, Finish and Duration stay in sync. Lesson minutes are derived as Duration minus Activity and stored as before, so totals, credit math, session rows and backups keep reading the same stored fields. A nullable endTime is added to each session and round-trips through backup; a backup without it still restores.

Locked decisions (user-confirmed in this quick task; IDs assigned here so the tasks can cite them):
- D-01: Start and Finish are native time wheels, exact to the minute. No 15-minute steps.
- D-02: Start plus Duration gives Finish. Start plus Finish gives Duration. Finish before Start is invalid. Activity may not exceed Duration. Crossing midnight is not supported.
- D-03: Lesson minutes = Duration minus Activity. Activity and Travel stay numeric fields.
- D-04: The 30/45/60 preset controls are removed.
- D-05: New-session defaults: Finish = now (to the minute); Start = Finish minus the last session's Duration; 45 minutes when there is no previous session. Students, subject, Activity and Travel still pre-fill from the last session.
- D-06: Storage: lessonMinutes, activityMinutes, travelMinutes and startTime are kept; a nullable endTime ("HH:MM") is added. No Dexie version change and no schemaVersion bump.
- D-07: Backup writes and reads endTime. A file without endTime restores with endTime null.
- D-08: Copy: rows "Start", "Finish", "Duration" with values such as "4:05 PM" and "0:47". The 02-UI-SPEC.md copy rows are updated and preset references removed.
- D-09: Unit tests cover the Start/Finish/Duration sync, Lesson = Duration minus Activity, Finish-before-Start rejection, and backup round trip with and without endTime.

Assumptions to confirm (the plan proceeds on these):
- A1: Duration = Lesson + Activity. Travel is outside Duration, which follows from "Lesson = Duration minus Activity".
- A2: Finish equal to Start is accepted as a 0:00 Duration, because zero-minute sessions are allowed. The request said Finish "must be after" Start. To make it strict, change the "before Start" checks in session.ts and sessionForm.ts to "not after".
- A3: Duration is typed as digits, read as whole minutes, and shown as h:mm. The iOS numeric keypad has no colon.
- A4: Lesson and Duration display as h:mm. Activity and Travel stay minute fields.
- A5: Clearing Start also clears Finish. A Finish past midnight blocks Save with a caption and is never stored.
- A6: Rows saved before this change have no endTime. The form computes Finish on open, and the next save stores it.

Purpose: a session becomes a start-and-finish record the instructor can check against the clock.
Output: domain, storage and backup changes, form UI, tests, and the planning docs that describe the presets.
</objective>
